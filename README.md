# 席決め・席替え

飲み会や懇親会で使う、スマートフォン向けの座席抽選アプリです。HTML / CSS / JavaScriptのみで動作し、外部ライブラリ・ビルド・サーバー処理は不要です。

## 使い方

1. 公開URL（GitHub Pagesなど）または`index.html`をブラウザで開きます。名簿は端末上のJSONファイルとして保存・読み込みできます。
2. 「列数・座席数を設定する」で各列の人数を指定し、「この配置で作成」を押します。初期値は4・5・5・4の18席。各列は縦に並び、全列を横一列に表示します。列数に応じて幅・間隔・文字を縮小し、座席の最小幅44pxでも収まらない場合のみ横スクロールします。列数と各列の人数は「−／＋」または中央の数字への直接入力で変更できます。1〜20列、各列1〜100席、合計200席まで対応します。
3. 「番号くじ」では「くじを引く」を押し、結果を確認して次の人へ渡します。
4. 「名前で席決め」では1行に1人ずつ入力して確定します。自分の名前→「抽選！」で1人ずつ抽選するか、「全員を一括シャッフル」でまとめて決めます。
5. 「位置を調整」を押すと、指・マウスで席を移動できます。キーボードでは席にフォーカスして矢印キーを使います。「調整を完了」で終了。「配置をリセット」で位置だけ戻します。

空行は無視します。同姓同名でも各行に内部参加者IDを付けて区別します。通常の名前一覧では欠席操作を非表示にしています。「欠席者を設定」を押すと各人の「欠席（対象外）」を切り替えられます。「欠席者設定を閉じる」でコンパクトな一覧へ戻り、欠席状態はそのまま残ります。欠席者の名前には小さく「欠席」と表示し、ボタンの横に欠席人数を表示します。欠席者は個別・一括抽選に含まれません。着席済みの人を欠席にする場合は確認後、その人の割り当てだけを解除します。欠席状態は今日の作業用で、保存名簿や前回配置に保存しません。

抽選対象者が席数を超えた場合も、警告を表示したうえで抽選できます。一括シャッフルは抽選対象者をランダムに並べ、席数分だけ選んでランダムな席へ配置します。残りは未配置として表示します。個別抽選は空席がある間だけ可能で、満席後は「未配置・空席なし」と表示します。席が多い場合は空席になります。一括シャッフルをやり直すと、抽選済みの人を含む全対象者を再抽選します。

番号と名前の抽選結果は別々に保持します。「抽選だけやり直す」は現在のモードだけをリセット。「参加者を変更する」は確認後に名前の結果をリセットします。

## 名簿ファイルを保存・開く

「名前で席決め」の「名簿ファイルを保存・開く」を開き、参加者を入力して名簿名を付け、「名簿を保存」を押します。名前の確定前でも書き出せます。例えば「3年1組_席替え.json」という名前で、ブラウザ標準のダウンロード機能を利用します。保存先や同名ファイルの扱いはブラウザの設定に従います。保存完了はアプリから判定できないため、ブラウザ側で保存先・結果を確認してください。

名簿は1ファイルに1つです。複数の名簿は別々のファイルとして管理できます。「名簿を開く」から端末内のJSONファイルを選択してください。PCのダウンロードフォルダや、iPhone/iPadの「ファイル」アプリ等を利用する通常のファイル選択です。ファイルを検証後、「名簿だけ使う」または、前回配置がある場合は「前回の配置も復元」を選べます。「読み込みを取り消す」では作業内容を変更しません。

「名簿だけ使う」は現在の座席構成で新しい席替えを始めます。ファイルに含まれた前回配置は、次の書き出し用データとして保持します。「前回の配置も復元」は座席構成・着席状態・手動位置を復元します。欠席状態はどちらも全員出席に戻るので、今日の欠席者を設定してください。現在の作業を置き換える際は確認します。番号くじで使用済みの席が消える復元は拒否し、番号の対応が変わる復元は確認後に番号くじだけをリセットします。

ファイルを開いて編集しても元のファイルは変更しません。保存は毎回ダウンロードです。不要なファイルは端末のファイル管理から削除できます。名簿データを外部へ送信する処理はありません。

## 前回配置をファイルに含める

1. 名前を確定し、抽選・位置調整を行います。
2. 「この配置を保存」を押して、前回配置をページ内の名簿データへ反映します。
3. 「名簿を保存」を押して、その前回配置を含むJSONファイルを書き出します。

**「この配置を保存」だけでは、端末の既存ファイルは更新されません。** ページ内に保持する前回配置は1件だけで、再度押すと確認後に更新します。途中の配置や空の配置も反映できます。名前の編集や再抽選だけでは前回配置は自動更新されません。反映後にさらに抽選・座席変更した場合、その変更も残したければ再度「この配置を保存」を押してください。

参加者情報が変わった場合、古い割り当てを誤って引き継がないよう、書き出し時に前回配置を除外する確認を表示します。新しい配置を含めるには名前を確定し、「この配置を保存」で更新してください。欠席状態と番号くじの結果はファイルに含めません。復元する画面サイズが異なる場合、手動位置は盤面内へ補正されることがあります。

## 席替え途中の座席変更

座席は列・行を表す安定した内部ID（例：`c0r0`）で識別します。各列の席数変更は列の末尾から追加・削除し、列数変更は右端から追加・削除します。残る列・行への名前の割り当てを保持し、新しい席だけ空席にします。表示番号は現在の列順・行順で常に1から連番になります。

削除対象に名前または番号くじの抽選結果がある場合、変更全体を拒否して元の状態を維持します。先に該当するモードの「抽選だけやり直す」を実行してください。未使用席だけなら削除できます。番号くじの既存番号と席の対応が変わる場合は、確認後に番号くじだけをリセットし、名前の結果は残します。確認を取り消すと変更しません。

座席構成を変更すると手動位置はすべて標準配置に戻ります。同じ構成での確定や通常の抽選・モード切替では維持します。「配置をリセット」は手動位置だけを戻します。

## ファイル形式と検証

JSONは`format: "seat-shuffle-roster"`、`version: 1`、`name`、`people: [{id, name}]`、`lastArrangement`を持ちます。前回配置がなければ`null`、ある場合は`columns`、`assignments: [[参加者ID, 座席ID]]`、`offsets: [[座席ID, {x, y}]]`、`savedAt`を保存します。座席IDは列・行から再現し、表示番号は保存しません。

読み込み時にJSON形式、形式識別子、バージョン、参加者情報・ID重複、座席数の上限、不正な参照、二重着席、移動量・保存日時を検証します。5MBを超えるファイルは拒否します。追加フィールドは取り込まず、対応する項目だけを扱います。破損・不正ファイルや読み込み失敗では現在の作業内容を維持し、通常の抽選を継続できます。

ブラウザ内部への永続保存は行いません。名簿・前回配置はページのメモリ上だけにあり、再読み込み・終了で失われます。端末に残すにはJSONファイルを書き出してください。旧版のlocalStorage保存処理・UIは廃止しました。旧版を利用済みの場合、既存のブラウザ内データは自動削除・移行しないため、不要な旧データはブラウザのサイトデータ管理で削除してください。

参加者名・座席設定・抽選結果は外部送信しません。Web Cryptoの棄却法とFisher–Yates法で、偏りを避けた重複なしの抽選を行います。現行のSafari / Chrome / Edge / Firefoxを想定しています。

アクセス記録のため、ページ読み込みごとに指定のGoogle Apps Scriptへ`app=seat-shuffle`のGETを1回だけ送信します。`number-slide-puzzle`と同じ`mode: 'no-cors'`、`cache: 'no-store'`、`credentials: 'omit'`、`keepalive: true`を使用します。応答を待たず、通信失敗は無視し、操作時の追加送信や再送は行いません。ブラウザ検証ではこの通信を捕捉し、実際のアクセス記録を増やさず送信回数と失敗時の動作を確認します。

## GitHub Pagesで公開

アプリのHTML・CSS・JavaScriptファイルをリポジトリのルートへ配置し、GitHubの **Settings → Pages → Deploy from a branch** で公開ブランチと **/ (root)** を指定します。すべて相対パスなのでプロジェクトのサブパスでも動作します。

## ファイル

- `index.html`：画面と入力フォーム
- `style.css`：スマートフォン優先のレスポンシブデザイン
- `app.js`：座席、抽選、名前入力、欠席設定、保存UI、ドラッグ操作
- `roster-file.js`：名簿ファイルの検証、読み込み、JSONダウンロード

## 確認項目

不均等配置と連番、全席の番号抽選、名前の個別抽選と再抽選防止、一括再抽選、人数超過・空席、320px幅とPC幅、調整中の指・マウス移動と位置リセットを確認します。

`tests/browser.cjs`は従来機能とレスポンシブ・アクセスカウンターの回帰検証、`tests/features.cjs`は実際のファイルダウンロード・選択・復元、欠席UIの開閉、超過・座席変更、不正ファイル・入出力失敗の追加検証です。localStorage/sessionStorageへアクセスしないこと、ファイル操作で外部通信しないことも確認します。`tests/support.cjs`がテスト用のローカルHTTPサーバーを起動します。アクセス記録は捕捉するため実際の記録を増やしません。

Node.js、Playwright、Google Chromeのある開発環境で実行します。Edgeの場合は`BROWSER_CHANNEL=msedge`を指定できます。Playwrightを共有配置している場合は`NODE_PATH`を設定してください。

```sh
node tests/browser.cjs
node tests/features.cjs
```

アプリの利用・公開にはこれらの開発ツールは不要です。タッチはブラウザのタッチイベントで検証しており、実機スマートフォンでの確認は別途必要です。
